# ENVO0323 后续学习总路线

[[学习目录|返回学习总目录]] · [[EEPROM-Driver-Outline|当前前置：EEPROM 驱动大纲]]

项目：ENVO0323 / STM32G431。规划日期：2026-10-02。

**EEPROM 后有 6 大阶段。前 4 阶段以现有工程为依据理解和复原；第 5、6 阶段是速度／位置外环的后续扩展设计，不把历史尝试当作当前已实现、已稳定的功能。**

这是一条学习顺序，不是六个已经独立存在的代码层。目前反馈处理、坐标变换、状态机和部分调制逻辑集中在 `app_motor_control.c`，不为学习大纲而先重构工程。

## 01：APP 基础组织

对应范围：`app_main`、`app_bringup`、`app_vofa` 与 BSP 的接口关系。

重点：初始化顺序、主循环与中断分工、EEPROM 自检、MT6816 异步请求与结果回调、统计变量和观测通路。

验收：能从 `main` 追踪一次读写或一次角度采样，说明谁调用谁、在哪里返回、数据如何交付。不要把 `App_Run()` 当成所有实时计算的入口。

## 02：采样与执行接口

对应范围：`adc`、`tim`、`app_pwm` 与 `app_bringup` 的采样处理。

重点：ADC 通道与相电流映射、PWM 同步触发、控制周期、零偏标定、电流单位换算，以及启动采样定时器和使能功率输出的区别。

验收：能说明“什么时候采样、哪一相数据放在哪、怎样转成 A、哪些操作真的会打开 PWM 输出”。先做离线计算和无输出检查，实机安全条件另行核对。

## 03：反馈与坐标变换

对应范围：`app_motor_control` 的编码器与电流反馈处理，不假定存在独立算法文件。

重点：角度计数跨零、方向、极对数、零位、电角度、速度估计、Clarke/Park、滤波、有效性和数据年龄。

验收：能解释从 MT6816 原始角度到电角度、从三相电流到 Id/Iq 的数据路径，并用离线样例检查边界、单位和符号。方向、相序、极对数和零位必须匹配硬件，不能仅因代码有默认值就认定正确。

## 04：电流环与状态机

对应范围：`app_current_pi`、`app_motor_control`、`app_pwm`。

重点：电流目标、PI、积分复位／预加载、参考与输出限幅、抗饱和、启动状态机、闭环切换、故障退出和调试记录。

验收：先贯通“采样 → 变换 → PI → 限幅 → 调制 → PWM → 反馈”，再在满足硬件安全条件后验证小电流跟踪。现有 PI 输出使用归一化指令，不能直接写成物理电压 V。

进入外环的门槛：反馈与角度可信、电流目标能跟踪、无异常持续饱和、保护与退出有效。编译通过不等于这些条件已满足。

## 05：速度环

性质：后续扩展；当前学习路线不授权直接改固件或开始硬件运行。

重点：机械转速参考与反馈、执行周期、速度 PI 输出 Iq 目标、目标斜坡、电流限制、级联抗饱和、模式切换和超速退出。

验收：能解释为什么速度控制器不直接写 PWM；先离线检查符号与限幅，再以稳定电流环为前提做实机验证。不靠提高超速阈值或取消保护来掩盖反馈方向问题。

## 06：位置环

性质：后续扩展；以有效位置反馈和稳定内环为前提。

重点：单圈／多圈定义、角度环绕、目标轨迹、位置控制器产生速度目标、速度／加速度／电流约束、到位判断、停止与保持的区别。

验收：能贯通“位置误差 → 速度目标 → Iq 目标 → 电流闭环”，并明确命令突变、反馈丢失、限位与饱和时如何安全退出。不默认位置、速度、电流三层都必须使用 PI。

## 每次学习怎样推进

1. 只选当前阶段的一小步，先看任务和完成标准。
2. 先自己说明函数要做什么、输入输出是什么，再尝试写 `.h` 或 `.c`。
3. 写好并保存后，发送 `1`，进行针对当前代码的评审；未经要求不直接替你实现全部内容。
4. 能解释后再做离线样例与编译验证，最后才安排有条件的实机验证。
5. 学到新的知识点再补学习日记；“建立大纲”不等于“已经掌握”。

## 安全与范围

本次只创建学习笔记，没有重写、清空、烧录或运行固件。所有硬件验证都默认 PWM 关闭，先确认采样标定与保护，采用合适的低压限流条件；涉及输出极性、相序、死区、对齐电流或保护阈值时另行确认风险和退出条件。

学习主要依据当前 `Software/ENVO0323` 的活动源码，不以 `_annotated` 讲解副本替代正在编译的实现。运行周期、默认参数和源码归属均可能随工程版本变化，实际开始阶段学习时重新核对。
